## Remarks
The `Session` class handles connecting to a Laserfiche server, logging in, maintaining a session, and logging out. Most classes that communicate with a Laserfiche server in the `Laserfiche.RepositoryAccess` namespace require a `Session` object. When a session is terminated, the objects associated with the `Session` object do not automatically become disassociated with the `Session` instance, but they can no longer save to or refresh state from the server until a new session is established. Whenever a LaserficheObject derived class associated with a session is modified, a reference to the class instance is stored in an internal list of pending objects maintained by the `Session` class. All of these changes can be saved or discarded en masse through the `Save` and `Discard` member functions. The `Session` class is not thread-safe. Multiple threads must synchronize access to an instance of the `Session` class.
